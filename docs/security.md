# 安全与隐私

## 1. 身份与会话

- 密码使用 BCrypt，成本因子不少于 12，并允许后续平滑升级；禁止可逆加密或明文。
- 密码 10～72 字符，至少包含字母和数字；允许密码管理器粘贴，不强制定期改密。
- 登录、注册和刷新 Token 必须限流；连续失败增加退避时间，日志不记录密码和 Token。
- Access Token 短期有效；Refresh Token 只保存哈希并轮换，重放已轮换 Token 时撤销同一会话族。
- 后台会话与前台隔离；公开生产环境后台应启用 MFA，MVP 至少预留字段和流程扩展点。
- 邮箱验证和密码重置使用至少 128 bit 随机一次性 Token，数据库只保存哈希；验证 30 分钟、重置 15 分钟后过期，使用后立即失效。
- Access Token 只存于浏览器内存；Refresh Token Cookie、CSRF、JWT claims 和密钥轮换遵守 API 规范。

## 2. 授权和输入输出

- 所有后台和资源所有权检查在服务端执行，默认拒绝。
- MyBatis 参数化查询；筛选与排序字段使用白名单，禁止拼接用户输入。
- DTO 做长度、格式和枚举校验；请求体设置合理上限。
- Markdown 渲染禁用原始 HTML或经严格白名单净化，禁止 script、事件属性、危险协议、iframe 和 CSS 注入。
- 用户正文禁止远程图片。头像仅使用系统默认资源或后续受控上传，避免跟踪像素、第三方替换和 SSRF。
- 用户文本默认转义；CSP 至少限制脚本来源，外链增加 `noopener noreferrer nofollow ugc`。
- 若使用 Cookie 传递 Refresh Token，必须使用 Secure、HttpOnly、SameSite，并对刷新、退出等状态操作实施 CSRF 防护。

## 3. 限流建议

| 场景 | 初始限制 |
|---|---|
| 登录 | 每 IP 每分钟 10 次；每账号每 15 分钟 10 次失败 |
| 注册 | 每 IP 每小时 5 次 |
| 发帖 | 每用户每 10 分钟 5 篇 |
| 评论 | 每用户每分钟 10 条 |
| 举报 | 每用户每天 20 次 |
| 搜索 | 每 IP 每分钟 60 次 |

限制值必须可配置。达到限制返回 429 和 `Retry-After`，但不得暴露内部风控策略。

- 单实例演示可使用 Bucket4j/Caffeine 本地桶；仅保证单进程范围内准确。
- 公开生产环境若运行多个应用实例，必须使用 Redis、API Gateway 或受信反向代理实施统一限流。
- 只信任来自配置中受信代理的 `Forwarded`/`X-Forwarded-For`，其他请求以直连地址为准。
- 账号维度限流在应用层执行，IP/网络维度可在网关执行；配置变更和命中量应可监控。

## 4. 上传和外部资源

- MVP 不提供通用上传接口或远程图片加载。启用头像上传时，只允许 JPEG、PNG、WebP，按实际文件头检测 MIME，限制 2 MB，重新编码并随机命名。
- 文件存储在非可执行目录或对象存储，禁止沿用原始路径和文件名。
- URL 字段只允许 HTTPS，解析后拒绝本地、回环、链路本地和私有网段，防止 SSRF。

## 5. 审计、日志与密钥

- 审核、删除、恢复、锁帖、置顶、角色变更、后台账号变更和用户状态变更记录操作者、目标、原因、时间和 requestId。
- 邮箱和 IP 在业务日志中脱敏；审计日志只保存 IP 哈希。正文不进入普通日志。
- 密钥、数据库密码和 Token 签名材料通过环境变量或密钥管理系统注入，禁止进入 Git、镜像和前端包。
- Mail Outbox 的收件邮箱和模板参数使用应用层信封加密，记录非敏感密钥版本；解密密钥仅从密钥管理系统注入，轮换期间允许读取旧版本、只使用新版本写入。
- 生产错误只返回统一消息；完整异常仅进入受控日志。
- 日志实现、级别、MDC、异常去重和敏感信息测试必须遵守 [logging-observability.md](logging-observability.md)。

## 6. 隐私与治理

- 注册时展示并记录用户协议、隐私政策版本及同意时间。
- 数据最小化：只收集账号、安全和社区功能所需信息；分析埋点不收集正文。
- 公开上线前必须提供数据导出、更正、注销/删除申请和申诉渠道。
- 审计日志建议保存 180 天；登录安全日志 90 天；具体周期上线前由法务和业务确认。
- 备份、客服导出和管理员界面遵循同等访问控制与脱敏要求。

## 7. 上线安全门槛

- 依赖漏洞扫描无已知严重漏洞。
- 完成越权、XSS、CSRF、SQL 注入、暴力登录、Token 重放和敏感信息泄露测试。
- HTTPS、CSP、安全 Cookie、CORS 白名单和生产日志脱敏已验证。
- 管理员默认密码已更换，演示账号不进入生产环境。

## 8. 敏感词处理

- 匹配前执行 Unicode NFKC、大小写归一化和连续空白规范化；不得修改用户保存的原文。
- 检查用户名、昵称、简介、帖子标题、正文、评论和举报描述，并按字段配置 REVIEW 或 REJECT。
- REJECT 优先于 REVIEW；向用户返回通用提示，不暴露具体命中词和绕过细节。
- MVP 不承诺拼音、拆字和图像识别；符号穿插策略须有自动化用例。
- 词库变更只影响新建和编辑内容；历史回扫通过独立、可审计的后台任务执行。

## 9. 合规确认

- 公开上线前由业务和法律负责人确认适用地区的隐私、内容治理、数据跨境和保存期限要求。
- 用户协议、隐私政策、申诉和注销流程须使用最终批准版本；技术文档不替代法律意见。
