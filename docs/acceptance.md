# 测试与验收

## 1. 测试策略

- 后端：Service 单元测试、Repository/Mapper 集成测试、Controller/API 集成测试。
- 前端：工具函数和核心组件使用 Vitest；关键页面状态与权限交互纳入组件测试。
- 端到端：Playwright 覆盖注册、登录、发帖、审核、评论、互动和后台管理主链路。
- 数据库集成测试使用真实 MySQL 8 容器或隔离实例，不以 H2 替代关键 SQL 行为。
- 每个缺陷修复应增加可复现该问题的回归测试。
- 架构检查应确认 Controller、Service 接口、ServiceImpl、Mapper 和 XML 的职责边界，没有将业务逻辑放入 Controller 或 SQL 映射文件。
- 日志测试应确认 requestId/traceId 能贯穿 Nuxt、Spring Boot、SQL 慢查询、邮件和后台任务，且异常只记录一次完整堆栈。

质量门槛：核心领域 Service 行覆盖率不低于 80%，整个后端和前端业务代码行覆盖率不低于 70%。覆盖率不是唯一质量指标，权限、状态流转和异常路径必须显式测试。

## 2. 自动化必测场景

### 账号与认证

- 使用唯一用户名和邮箱注册成功；重复用户名或邮箱返回 409。
- 用户名或邮箱可登录；错误凭据返回统一信息，不泄露账号是否存在。
- Refresh Token 轮换后旧 Token 不能再次使用；退出后不能刷新。
- 未验证邮箱的账号不能正常登录；验证与重置 Token 过期、重复使用和暴力尝试均被拒绝。
- 密码重置后历史 Refresh Token 全部失效，Access Token 因 tokenVersion 变化被拒绝。
- 禁用用户不能登录和写入；已有 Access Token 在服务端状态校验后失效。
- 前台 Token 不能访问后台，后台 Token 不能冒充前台用户。

### 帖子和评论

- 游客可浏览公开内容，但创建操作返回 401。
- 用户不能修改或删除其他用户内容，返回 403。
- 新用户帖子进入待审核；通过后公开，驳回原因仅作者和后台可见。
- 已公开帖子编辑时旧版继续展示，新版通过后替换。
- 待审或驳回版本的标题、板块和正文均不会泄露到公开接口、SSR、搜索或 sitemap。
- 已公开评论不能编辑；删除后重新发布会获得新楼层。
- 锁帖不能编辑或新增评论；软删除后列表和详情不公开，管理员可恢复。
- 评论楼层唯一且删除后不重排；未通过评论不增加公开评论数。

### 互动、列表和搜索

- 重复点赞、收藏不产生重复记录或计数；取消操作同样幂等。
- 使用相同 clientRequestId 重试创建帖子或评论只产生一条数据；同一用户使用相同 ID 提交不同内容返回 409。
- 浏览刷新不在同一去重周期内重复计数。
- 列表默认 20 条、最大 100；非法页码、页大小和排序返回 400。
- 置顶、最新、热门和精华排序符合产品规则。
- 搜索不返回待审、驳回、删除或不可见板块中的内容。
- MySQL FULLTEXT ngram 对中英文测试词、标题权重、更新和删除后的索引结果符合预期。

### 后台与安全

- 运营人员不能管理后台账号、角色、用户状态或系统配置。
- 最后一个管理员不能被删除或禁用。
- 审核、删除、恢复、锁定、置顶、权限和状态变更产生完整审计记录。
- `<script>`、事件属性、危险协议、iframe 和畸形 Markdown 不会执行。
- 登录、注册、发帖、评论、举报和搜索达到阈值时返回 429。
- SQL 注入、越权访问、Token 重放、CSRF 和敏感信息泄露测试通过。
- 正文和头像均不能加载用户提供的远程图片；外链协议、rel 属性和跳转行为符合安全规范。
- Mapper 接口不含 SQL 注解，业务代码不调用 BaseMapper CRUD、IService 或 QueryWrapper；所有项目 SQL 均可在 XML 中定位。
- 官方系统账号不能普通登录、禁用或删除，后台代表发布时记录真实操作者。
- 浏览量按 Asia/Shanghai 日期做应用层近似去重，爬虫和预取不计数；每日聚合和累计浏览数保持一致。
- 集群定时任务同一时刻只执行一次，失败邮件进入可观测的死信状态。
- 业务异常、系统异常、数据库异常和外部服务失败均可通过 requestId 定位；日志中不存在密码、Token、验证码、Cookie、完整邮箱、正文或解密后的邮件地址。

## 3. 功能验收标准

以下条件必须全部满足：

1. 按部署文档从空数据库执行迁移并启动前后端，无需手工改表。
2. 游客可浏览首页、板块、帖子和搜索公开内容。
3. 用户可注册、登录、退出、更新资料并完成发帖、评论、点赞和收藏。
4. 权限和内容所有权在接口层正确阻止未登录与越权操作。
5. 新用户与敏感词审核规则生效，作者能看到待审和驳回原因。
6. 运营人员能管理板块和内容；管理员能额外管理用户、后台账号和角色。
7. 帖子、评论、用户及板块状态按文档流转，软删除内容可由管理员恢复。
8. 所有列表分页，搜索和排序结果符合规则。
9. Markdown 渲染通过 XSS 验证，密码、Token、邮箱和正文不出现在不应出现的日志中。
10. OpenAPI 与实际接口一致，自动化测试和构建在干净环境中全部通过。
11. 前端页面与组件按开发规范拆分，入口文件不包含页面业务实现。
12. 公开页面具有唯一且能描述内容的 title、description、canonical、Open Graph 元数据和可抓取正文；站点提供 robots.txt 与 sitemap.xml。
13. Nuxt SSR 首次响应包含公开正文；站内搜索页为 `noindex,follow`，帖子旧 slug 301 到规范 URL。
14. 邮箱验证、密码找回、审核结果、账号禁用和举报结果邮件可以可靠投递与安全重试。

## 4. 性能验收

在约 10 万帖子、100 万评论的基准数据下，使用 4 vCPU、8 GB 内存的应用节点和独立 MySQL 8 实例；预热 5 分钟后，以 100 个并发虚拟用户、80% 读取/20% 写入的流量持续测试 30 分钟：

- 首页、板块列表和普通帖子列表 P95 小于 1 秒。
- 帖子详情及首屏评论 P95 小于 1 秒。
- 登录和发帖接口 P95 小于 1.5 秒（不含外部服务）。
- 关键词搜索 P95 小于 2 秒。
- API 5xx 比例低于 0.1%。
- 目标稳定吞吐不低于 100 RPS，数据库连接池使用率不得持续超过 80%，超过 500ms 的 SQL 必须单独分析。

容量测试允许的 5xx 比例低于 0.1%；功能与集成测试不允许出现非预期 5xx。测试报告必须记录硬件、并发数、持续时间、数据规模、读写比例、吞吐、预热时间和数据库配置。

## 5. 发布验收清单

- 数据库迁移在备份副本演练成功，并验证回滚或前滚修复方案。
- 生产环境变量、密钥、HTTPS、CORS、Cookie、CSP 和日志级别正确。
- 不存在默认密码、测试管理员、调试接口或演示数据。
- 监控可观察健康状态、错误率、延迟、数据库连接池和磁盘容量。
- 邮件失败、审核积压、限流异常、Token 重放、慢 SQL 和 SSR/API 错误率已配置告警。
- 已准备数据库备份、恢复演练、故障联系人和回滚步骤。
- 产品、开发、测试和运营负责人共同签署验收结果及已知问题。
