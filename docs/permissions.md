# 角色与权限

## 1. 角色定义

- 游客：未登录访问者。
- 注册用户：已登录且状态正常的前台用户。
- 运营人员：拥有内容运营权限的后台账号。
- 管理员：拥有系统与权限管理能力的后台账号。

后台采用固定角色授权。MVP 只内置 `OPERATOR` 和 `ADMIN`，角色编码直接保存在后台账号中；权限映射维护在后端代码中，不建立角色或权限表，不提供自定义角色。权限判断以后端为准，前端隐藏按钮不能替代授权校验。管理员不能删除最后一个有效管理员，也不能禁用自己的当前会话账号。

## 3. 边界规则

- 注册用户只能修改或删除自己的内容；服务端必须校验资源所有权。
- 运营人员不得修改角色、安全配置或管理员账号。
- 板块不物理删除，只允许禁用或归档。
- 管理员处置内容必须填写原因，不得静默篡改用户正文。
- 后台 Token 不得调用前台写接口，前台 Token 不得调用 `/api/admin/**`。
- “HOOTOOM 官方”是不可登录的系统保护账号；运营人员只能通过后台官方内容接口代表其发布，审计日志永久记录真实操作者。

## 4. 权限编码

```text
dashboard:read
user:read
user:status:update
category:read
category:create
category:update
content:read
content:review
content:moderate
report:read
report:resolve
sensitive-word:manage
audit-log:read
admin-account:manage
role:manage
system-config:manage
```

权限编码作为后端常量使用，角色到权限的映射随代码版本管理。未来出现第三种角色或自定义权限需求时，再通过新迁移增加角色、权限和关联表。
