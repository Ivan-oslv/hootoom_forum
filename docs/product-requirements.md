# 产品需求

## 1. 背景与目标

HOOTOOM Forum 是官网的官方客户社区，承担公告发布、广告经验沉淀、用户交流、问题反馈和运营互动。目标是降低重复咨询、提高问题自助解决率，并为后续工单、知识库和统一账号预留扩展点。

## 2. MVP 范围

### 必须交付

- 邮箱、用户名和密码注册；验证邮箱后激活账号；用户名或邮箱加密码登录；退出、刷新登录态和找回密码。
- 修改昵称和简介，并从系统内置头像中选择头像。
- 板块、帖子、评论的浏览和分页。
- 注册用户发布、编辑、软删除自己的帖子与评论。
- 点赞、取消点赞、收藏、取消收藏。
- 按标题和正文搜索公开帖子，并按板块筛选。
- 首页展示推荐板块、最新帖、热门帖和官方公告。
- 后台用户、板块、内容审核、举报、敏感词、后台账号角色分配和审计日志管理。
- 初始化演示数据、OpenAPI 文档和核心流程自动化测试。

### 可延后

- 标签和标签筛选。
- 自定义头像上传；MVP 仅允许选择系统内置头像。
- 评论举报；MVP 必须支持帖子举报。

### 明确不做

- 多级评论、私信、实时通知、积分、等级、勋章。
- 短信、第三方登录、视频和普通文件附件。
- 工单、独立知识库、Elasticsearch、Redis 强依赖。
- 官网统一账号、CRM、多语言、多租户和原生 App。

## 3. 账号和板块

- 游客只访问公开内容；注册用户可参与社区互动。
- 前后台账号分表、分入口、分 Token audience。
- 官方内容通过专用“HOOTOOM 官方”前台身份发布，审计日志记录真实后台操作者。
- 禁用用户不能登录或写入，历史公开内容继续展示。
- 注册后账号处于待验证状态；验证链接 30 分钟有效，可受限流控制重新发送。
- 找回密码通过一次性邮件链接完成；成功后撤销该用户全部 Refresh Token 并递增 Token 版本。
- 注销不纳入 MVP；公开上线前必须提供自助申请或人工处理流程。
- 初始板块：官方公告、平台政策更新、Facebook、Google、TikTok、开户与账户问题、投放优化问答、教程与知识库、案例复盘、建议反馈。
- 板块支持名称、唯一 slug、简介、图标、排序、推荐标记和状态。禁用板块不接受新内容；归档板块不出现在列表，原公开帖子仍可直链访问。

## 4. 内容规则

### 帖子

- 标题 5～120 字符；Markdown 正文 10～50,000 字符；一篇帖子属于一个板块。
- 帖子内容通过版本表管理。作者编辑已公开帖子时创建待审版本，旧发布版本继续公开；待审版本通过后原子切换为新发布版本，驳回不影响旧版本。
- 删除为软删除，帖子及评论不再公开，管理员可恢复。
- 锁帖后不能评论或编辑，仍允许点赞和收藏。
- 置顶分板块和全站；MVP 实现板块置顶，全站置顶仅供官方公告。
- 精华、官方、置顶是独立标记，不是生命周期状态。

### 评论

- 内容 1～5,000 字符，仅支持一级评论。
- 可记录 `reply_to_comment_id` 展示回复对象，但仍平级排列。
- 楼层号创建时确定，删除后不重排。
- 未公开评论可编辑；已公开评论不允许编辑，用户如需修改应删除后重新发布。用户可软删除自己的评论；管理员删除必须填写原因，并保留“该评论已删除”占位。

### Markdown 与互动

- 只提供 Markdown 编辑和预览。服务端保存原文并生成白名单净化后的 HTML。
- 不支持 iframe、附件、视频或正文远程图片；外链仅允许 HTTP/HTTPS。头像只允许系统默认头像或后续受控上传，MVP 不加载用户提供的远程头像 URL。
- 点赞和收藏接口幂等，同一用户对同一帖子各至多一条记录。
- 浏览量按用户或匿名会话、帖子及 Asia/Shanghai 自然日做近似去重。MVP 使用短期应用缓存与匿名 Cookie 控制重复计数，不保存逐用户浏览明细；多实例生产使用 Redis 共享去重键。已识别爬虫和预取请求不计数。
- 帖子保存浏览、点赞、收藏和评论计数快照，关系表和有效评论是事实来源。

## 5. 审核和状态

- 新用户：注册未满 7 天或累计通过帖子少于 3 篇；其新帖进入待审核。
- 其他用户帖子默认公开，命中敏感词则待审核；评论规则相同。
- 驳回必须填写原因，作者可查看并修改后重提。
- 举报类型：垃圾广告、违法违规、骚扰攻击、侵犯权益、虚假信息、其他。
- 同一用户对同一目标只能存在一条未关闭举报。
- 删除、锁定、审核、权限变更和禁用用户均写审计日志。

| 对象 | 状态 |
|---|---|
| 用户 | PENDING、ACTIVE、DISABLED |
| 板块 | ACTIVE、DISABLED、ARCHIVED |
| 帖子审核 | PENDING、APPROVED、REJECTED |
| 帖子业务 | NORMAL、LOCKED、DELETED |
| 评论审核 | PENDING、APPROVED、REJECTED |
| 评论业务 | NORMAL、DELETED |
| 举报 | PENDING、RESOLVED、REJECTED |

审核和业务状态分别存储；只有已通过、未删除的内容公开。权限详见 [permissions.md](permissions.md)。

## 6. 页面

- 前台：首页、板块列表、板块详情、帖子详情、发帖/编辑、搜索、用户中心、登录和注册。
- 后台：仪表盘、用户、板块、内容审核、举报、敏感词、后台账号及固定角色分配、审计日志。
- 所有页面必须覆盖空、加载、失败和无权限状态；支持 360px 以上响应式布局及 WCAG 2.1 AA 的键盘、焦点、对比度和表单标签要求。

## 7. 排序、分页和搜索

- 默认每页 20 条，可选 10/20/50，最大 100。
- 最新排序：`last_activity_at DESC, id DESC`；有效新评论更新活跃时间。
- 热门排序：过去 7 天内 `浏览 × 1 + 点赞 × 5 + 有效评论 × 8`，同分按活跃时间。
- 精华视图仅显示精华帖；置顶帖优先，置顶组内按置顶时间倒序。
- 搜索使用 MySQL FULLTEXT ngram 检索已发布版本的标题和 Markdown 正文，只返回公开内容；关键词 2～50 字符，标题权重高于正文，再按活跃时间排序。

## 8. 通知与删除行为

- 邮件通知用于邮箱验证、找回密码、帖子审核结果、账号禁用和举报处理结果；普通评论回复通知不属于 MVP。
- 删除帖子后保留点赞、收藏、评论和版本数据但不公开；恢复后重新计算统计快照。
- 删除评论后其回复关系保留，界面展示“回复的评论已删除”。
- 删除内容关联的待处理举报由处理人结案，不自动丢弃举报记录。
- 归档板块可由管理员恢复；帖子可在后台迁移到正常板块，迁移需审计。
- 软删除数据 MVP 不自动物理清理；后续清理需审批、备份和独立迁移任务。
- 永久删除且无恢复可能的公开帖子返回 HTTP 410；临时隐藏或无权访问返回 404，避免泄露资源状态。

## 9. 成功指标

按月观察注册用户、发帖用户、有效帖子、搜索后访问率、获得有效回复的问题比例、重复客服问题变化和审核时长。业务负责人在上线前补录目标值；埋点不得采集正文或不必要的个人信息。
